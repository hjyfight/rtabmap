# MITI 三维地图与二维栅格地图

两个地图并排显示：左侧保留原三维点云、墙面、语义标签和位姿；中间显示二维
栅格，右侧继续显示彩色图和深度图。第二个窗口使用 MITI 原生 Occupancy Grid
图层，默认正交俯视、固定 `map` 坐标系，并叠加机器人位置箭头和轨迹。

## 数据来源

第二个窗口现在使用 `/miti/grid_map`（`nav_msgs/msg/OccupancyGrid`）。独立的
`grid_projection` 节点读取 `/miti/clean_map` 完整快照，输出按地面高度筛选后的
二维地图。该快照来自原始 `/cloud_map` 的[动态残影清理](dynamic_cloud.md)；原始点云、
位姿以及 RTAB-Map 原生 `/map` 不被修改。

处理过程：

1. 在地图低处寻找有足够观测支持的近水平面，并用真实定位参考点限制地面搜索，
   避免将天花板当作地面。地面模型是 `z = ax + by + c`，允许小幅倾斜。
2. 计算每个点相对地面的高度，默认仅将 **0.15～1.60 m** 范围内的点作为障碍；
   高处结构被排除，并移除缺少邻居支持的孤立障碍点。
3. 有观测支持的地面单元标白；高度范围内的障碍单元标黑，同一单元障碍优先。
   没有观测支持的位置保留灰色，不填满门洞、遮挡区或整个房间的包围区域。
4. 每个新快照完整替换输出，不叠加旧栅格。默认最多每秒转换一次，忙时保留最新
   点云；地图静止时显示保留的最后一张地图。回环后的新快照会重新转换。

分辨率默认 5 cm。黑色 `100` 表示该高度范围的障碍，白色 `0` 表示观测到的
地面，灰色 `-1` 表示未知。界面显示高度范围和最近接收时间。地面无法确认时
输出未知区域并提示等待，不把未知区域强行改为空闲。

参数在 `config/grid_projection.yaml`，修改后重启展示服务生效。地面参考点
优先使用 `/robot_pose`；没有实时里程计的旧地图可使用 `/mapGraph` 的图节点
位置。设置 `MITI_GRID=0` 可以不启动该转换节点。

这一版按单层、近似平面的地面处理，多层楼、明显台阶或大起伏地形需要局部地面
模型。白色只代表地面观测，不是经过机器人尺寸、坡度、净空和代价膨胀验证的导航
通行区域。高度区间内的家具、人体及原点云残影仍可能保留。

没有从当前机器人位置向完整历史点云盲目投射射线：全局点云缺少每个点的实际
采集原点，这样做可能穿过墙壁错误清空遮挡区。需要完整空闲空间更新时，应使用
每帧扫描及其对应位姿进行射线处理。此修复首先解决高处结构造成的大片误投影。

## 使用与已有布局更新

```bash
bash scripts/start_miti.sh
```

首次使用：打开 `http://localhost:3000/rtabmap.html`，选择“应用完整项目布局”。

已有项目布局：打开 `http://localhost:3000/rtabmap.html?refresh=1`，入口会刷新
脚本缓存、备份浏览器配置，并自动返回主页面。迁移只执行一次：将原三维地图
紧邻的空白 `3D Scene` 改为栅格窗口；若该窗口已配置数据或锁定，则在原地图
旁新建窗口。已有相机、日志、三维视角和裁剪设置保留。用户之后移除栅格窗口，
不会在每次刷新时强制加回来。

第二个窗口收到地图后自动适应边界。可以滚轮缩放、右键拖动，点击“适应地图”
恢复完整俯视图。原三维窗口仍可正常旋转。两个窗口均使用 `map` 固定坐标系。

已有栅格窗口会一次性关闭旧 `/map` 图层、切换到过滤后的话题，保留布局、缩放
和色彩设置。原三维窗口不参与这次迁移。

若手工创建场景：添加 `/miti/grid_map`，类型选择 `Occupancy Grid`，启用可见；固定与
显示坐标系均设为 `map`，关闭 `Sync timestamps`，视图选正交俯视。
桥接进程若通过自定义 `BRIDGE_TOPIC_WHITELIST` 启动，需要包含 `^/miti/.*$`。
