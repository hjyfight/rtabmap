## 判断与下一步

点云明显稀疏、成批到达，IMU 缓冲溢出并出现 TF 时刻缺失；去畸变失败后仍
输出未经完整补偿的扫描。这些已观测故障足以影响运动建图，需先处理，不能
仅通过放宽 ICP 阈值或调整栅格显示来验收地图精度。

1. 恢复 Go2 到 Orin 的连接，确认当前 IP 和发送端状态。
2. 在停止传感器和建图后完成各机校时。本次没有修改系统时钟。
3. 优先用 Go2 到 Orin 的有线传感器链路做对照，工作站仍可无线显示；如果
   必须无线，再基于实测吞吐设计传输降载和点云/IMU 的时序处理。
4. 输入稳定、去畸变不再报错后，新建独立数据库进行低速直线与转向采集。
   保留本次数据库供比较；已有错误拼接不会因刷新页面或切换显示选项而修复。

截图中的相机朝向警告来自 MITI 的相机光轴箭头配置。当前未启动相机，因此
缺少相机 TF。它影响位姿箭头显示，不能解释全部点云重影；不要编造相机外参
来消除警告。显示层可以选择雷达坐标轴，和建图质量排查分别处理。

本次只完成诊断，没有执行用户设备启停、校时、网络切换或修改 ICP 参数。
Orin 仍按用户要求手动操作，传感器恢复后尚需实机验证。

## 后续有线排查：Go2 无线驱动初始化卡住

用户确认 Go2 已开机并重新接上工作站网线后，有线 SSH
`unitree@192.168.123.18` 恢复。此时检查到：

- Go2 只有 `eth0=192.168.123.18/24`，没有 `wlan0`，没有默认路由；
  NetworkManager 仍保存原 Wi-Fi 配置，但没有可用无线设备。
- USB 网卡枚举为 `2357:0147`，启动日志的产品名为 `AIC8800DC`。
  `aic8800_fdrv` 模块在 `/proc/modules` 中持续显示 `Loading`，
  `/sys/module/aic8800_fdrv/initstate` 为 `coming`。
- 内核持续输出 `WARN urb submitted to disabled ep` 与
  `usb submit msg rx urb fail:-2`。用户单独拔插 USB 网卡后，
  错误变为 `usb submit msg rx urb fail:-19`，仍未生成无线接口。
  `lsusb` 和部分 USB 字符串属性查询也会挂起；本次创建的挂起查询已清理。
- Go2 雷达驱动和发送端未运行。Orin 原接收进程仍向
  `192.168.1.104:7447` 发起连接；其到 `192.168.123.18` 的路由经
  Wi-Fi 网关 `192.168.1.1`，不是这次恢复的工作站直连网线。
- 用户随后手动停止了 Orin 的接收和建图，已通过进程检查确认；
  Orin 的 `NTPSynchronized=yes`，Go2 仍为 `no`。

这次断连已定位到 Go2 的 USB 无线网卡/驱动初始化失败，不能仅通过修改
Orin 接收 IP 或重启 SLAM 解决。现有证据尚不能区分驱动缺陷、USB 连接
或供电问题，也不能证明网卡永久损坏。

单独拔插未恢复后，建议用户保留管理网线，在机器狗停止运动时手动重启
Go2 机载 Ubuntu，并在系统启动后插回 USB 网卡。必须以启动标识/运行时间、
无线接口出现、实际 IPv4 和 Orin 到该地址的连接验证为准，不能只凭
“执行过重启”判断恢复。此后仍需完成 Go2 校时、实测点云/IMU 连续接收
与去畸变验证，再使用新数据库评估运动建图。

用户要求继续使用 Go2 Wi-Fi。之后已确认一次真实重启（启动标识改变），
但同一初始化错误再次出现。保存的 `TP-LINK_6E07_2.4G` 配置仍启用自动
连接，IPv4 使用 DHCP；历史 `.104` 地址需在无线接口恢复后重新确认。
本次尚未修改无线驱动、Wi-Fi 密码或系统网络配置。

进一步读取安装源码发现，`aicwf_usb_submit_msg_rx_urb()` 在提交失败后
将缓冲放回空闲队列、等待 100 ms，却仍返回 0；外层
`aicwf_usb_msg_rx_submit_all_urb()` 因此反复重试，无法退出初始化。
这解释了当前驱动卡住，但尚不能单独解释第一次 USB 端点被禁用的原因。
已安装模块与 `/AIC8800` 中的编译产物哈希一致，驱动版本为 6.4.3.0；
历史成功记录也使用同一 release 标记，不能据此宣称是最近更换驱动导致。

历史 USB 路径包含扩展坞后的 `1-2.1`（GenesysLogic USB2.1 Hub），
当前为直连 `1-2`；当天也存在 `1-2` 初始化成功记录，所以扩展坞并非已证实
的必要条件。最近一次重启中 USB 网卡在开机约 8 秒枚举，约 16 秒开始失败。
下一项最小验证是先拔下网卡、用户手动重启，确认系统完成启动后再插回，
区分开机初始化时序问题与持续的 USB/驱动故障。

## 本次 Wi-Fi 恢复结果

用户拔下无线网卡并手动重启，确认系统服务启动、无线驱动未加载后再插入。
本次网卡在开机约 353 秒初始化成功，模块状态变为 `live`，`wlan0` 自动连回
`TP-LINK_6E07_2.4G`，重新取得 `192.168.1.104/24`。Go2 与 Orin
`192.168.1.103` 双向各 5 次 ping 均成功。未更换驱动、固件或 Wi-Fi 配置。
这验证了本次恢复方法有效，并提示启动初始化时序相关；尚不能据一次恢复
保证以后每次冷启动都正常，也未实施持久的驱动修复。

重启后发现 Go2 无线省电重新开启。用户手动关闭并通过 NetworkManager
保存 `802-11-wireless.powersave=2`，已读回确认 `Power save: off`。
Go2 时钟仍落后约 59 秒；在采集停止时，用户运行临时校时工具，输出
`offset=59.234247s, minimum RTT=0.001328s`。这是本次手动校时，不能等同于
持续 NTP 同步已配置完成。工作站和 Orin 报告 NTP 已同步。

用户重新手动启动 Go2 点云 + IMU 发送端和 Orin 接收端后，15 秒订阅统计：

- 原始点云 96 帧，约 6.4 Hz；最长到达间隔 1.124 秒，最长帧时间戳间隔
  1.1 秒，无倒序，每帧末次统计 19,968 点。
- 原始 IMU 2,919 条，最长时间戳间隔 0.006 秒，无倒序；仍有成批到达。
- 点云消息年龄中位数 2.38 秒，IMU 2.19 秒。需结合跨机时钟测量解释，
  不能将该数值全部作为无线传输延迟。
- Go2 TCP 连接确认直达 Orin 无线地址；一次快照发送队列约 199 KB，
  RTT 43.6 ms，瞬时 delivery_rate 33.2 Mbps。这不是完整吞吐验收。

原始统计保存在 `logs/go2_orin/wifi_recovery_sensor_20261112.json`。
