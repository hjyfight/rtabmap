有几处容易把现有功能理解得过宽，需要单独说明。

1. **标定参数与标定完成是两件事。** 启动文件读取相机内参及 `CAM_*` 外参，并对非法数值作检查。语义启动脚本在变量未赋值时仍有示例默认值和提示。代码能接受一组外参，只能证明参数配置功能存在；尚需要可追溯的实测标定结果，才能判定空间配准精度满足要求。现有记录也明确保留了实际外参误差未验证的限制。

2. **50 ms 是配对容差，不是本次测得的同步误差。** 主配置的 `rgbd_sync_max_interval=0.05` 作用于 RGB、深度和 CameraInfo，持续校验器同样按该值判断。它允许超过 10 ms 的数据对进入链路，不能作为“已经满足 10 ms”的证据；也不能单凭该参数断言实际误差恰好为 50 ms。传感器采集时刻、设备时钟偏差、消息接收间隔和端到端处理耗时应分别评价。历史按“近同时到达”配对得到的时间戳差也不是经校准的采集同步误差。

3. **现有融合确实存在，但范围有边界。** 主链路中，LiDAR 提供几何里程计和地图，IMU 提供方向、旋转去畸变与重力约束，RGB-D 提供视觉回环信息和物体语义投影。地图几何默认来自 LiDAR，深度点云没有在该主配置中直接拼入地图。标准并不要求所有系统都采用同一种融合算法，但需证明实际路径覆盖其规定的关联、语义对齐、冲突处理和输出要求。物体位置多帧融合、地图点云着色、跨类别名称归一，都不能单独覆盖这些完整要求。

4. **对象 ID 与动态类别标记不足以证明完整跟踪。** 当前 `dynamic_classes` 为 person、cat、dog；这是一种类别规则，并非根据运动测量判定所有物体是否运动。动态对象保留最新位置，超时后移除；当前对象消息没有速度、方向和预测轨迹字段。项目有基础位置关联能力，但标准 5.2.1 b 所列完整动态状态输出尚未覆盖。

5. **标签稳定与环境变化更新存在不同要求。** YOLOE 默认最近 6 个已处理关键帧中出现至少 4 次才确认静态标签，确认后漏检不会自动删除。该设计有助于减少显示闪烁，但现有代码与测试没有证明静态物体移走后会正确删除旧地图元素。回环校正对象锚点、更新图位姿，也不能单独证明子地图拼接和多时相环境变化对齐合格。

6. **实例分割与完整环境解析的覆盖范围不同。** 目前模型输出实例掩膜，掩膜参与深度筛选和三维定位；尚未形成标准所列全部地形、道路、建筑、植被、障碍和区域关系的统一环境解析输出。YOLOE 的内置类别数量以及推理成功次数，不是识别准确率。已有文档记录了现场高置信度误识别，且没有给出标准目标集的准确率、召回率、漏检率和虚警率报告。

7. **接口有部分标准所需信息，但信息链尚不完整。** `SemanticObject` 包含对象 ID、标签、置信度、动态标记和观测锚点；`SemanticMap` 包含 Header、map_key、map_uuid。对象尺寸和深度离散程度虽在内部计算，却没有作为完整对象属性及不确定性结构对外传递。输入拒绝状态是独立 JSON 计数，也不是随每个特征传递的传感器健康及质量信息。地图历史 epoch 和旧库兼容检查不等于面向使用方的版本回退及操作审计接口。

两份大纲还存在需要固定适用口径的地方。

- 融合大纲表 5 第 1 项的合格判据写“至少接入两种模态数据”，而 5.1.1 a、b 以及陪试品描述列出了可见光、红外、LiDAR、声学。当前 RGB-D、LiDAR、IMU 具备多模态基础；不能据此自动免除详细步骤中其余模态的要求，也不能仅因没有四类模态就否认最低两模态条件。适用范围和未配置模态的处理应在正式验证基线中写清楚。
- 建模大纲 5.1.1 a 写“平台配置范围内”的数据，具有配置适用性；但陪试品仍列出红外、声学。项目内未见对应处理链，只能判断该项目当前未证明这些能力，不能推断外部单位一定没有相关设备。
- 外部授时 ≤1 ms 是涉及集群或外部系统协同时的条件要求，不能无条件套用，也不能因存在 ROS 网络通信就直接判定其适用或不适用。
- “宜＜5 cm / 宜＜2 cm / 宜＜1°”属于大纲中的推荐措辞，应与“应”和“不得”等强制要求区分；若任务或合同采用为验收限值，则按对应文件判定。
